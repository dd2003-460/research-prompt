# R0.3-xdomain — 跨域泛化测试（GPU → LLM 选型）

# origin: ai

## 动机

R0.3 = 18/20 (σ=0) 是 GPU 硬件选型任务的最优 prompt。
decomp bench 的核心发现：方法论「拆什么」跨域迁移成功，但「怎么拆得严」需显式注入。
本实验测试：R0.3 的格式契约能否直接迁移到 LLM 模型选型任务（同构：候选→叶子物理量）？

## 设计

- Prompt：R0.3 核心规则+格式要求不变，只替换任务描述（GPU 选型 → LLM 7B 级选型）
- 候选：Llama-3.1-8B, Mistral-7B-v0.3, Qwen2.5-7B, Gemma-2-9B
- 约束：A100 80GB SXM + vLLM + FP16/INT4 + 2K in/500 out + 90% prefix cache + ≥5 req/s
- 执行：qwen3.8-27b temp=0.7 max_tokens=32000, n=3
- 评分：简化版（五节结构×2分 + 5内容维度×2分 = 满分20）

## 判读

**部分迁移成功。** 内容维度全部满分（C1-C5 都拿到），但结构稳定性崩塌：

1. **run1 格式失效**（S=0）：没有输出五节标题，而是自由格式的"草稿"。与 T34 (R0.3C4) 的失败模式相同——模型在陌生领域切换到"研究模式"而非"报告模式"。

2. **run2/run3 完美迁移**（S=10, C=10）：五节结构完整，所有内容维度达标。说明 R0.3 的格式契约在 LLM 选型任务上**可以**工作，只是不稳定。

3. **方差爆炸**（σ=0 → 4.71）：GPU 任务上 R0.3 是 18/20 σ=0（三次完全一致），LLM 任务上变成 10/20/20（一次崩塌两次满分）。

### 根因

- GPU 选型是模型的"舒适区"：训练数据中有大量 GPU benchmark、TCO 分析、硬件对比。格式契约 + 领域知识双保险 → σ=0。
- LLM 选型是"边缘区"：模型对 7B 级开源模型的参数细节（KV heads、GQA 配置、许可证条款）记忆不够精确。当需要"调研"时，注意力从格式合规转移到信息搜索 → 格式契约失效。
- 这与 decomp bench 的发现一致：「拆什么」能迁移（内容维度全满分），「怎么拆得严」不能自发内化（结构稳定性依赖领域熟悉度）。

## 结论

**R0.3 的格式契约跨域迁移率 = 67%（2/3 runs 保持结构）。**

- 在模型熟悉的领域（GPU 硬件）：σ=0，完美稳定
- 在模型半熟悉的领域（LLM 选型）：σ=4.71，1/3 概率格式崩塌
- 预测：在完全陌生的领域（如生物信息学、量子计算）：崩塌率会更高

**实践建议**：跨域使用 R0.3 时，需要在 prompt 中追加"格式优先级"指令（"无论内容多复杂，五节结构不得省略"），或接受 1/3 的 re-run 成本。
