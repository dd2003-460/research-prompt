# qwen3.8-bare run1

**任务**：在常见的候选硬件里，哪一种每完成一个任务的成本最低？

**约束**：
- 27B 模型（FP16 约 54GB）
- 64K 上下文
- 20 tok/s 最低吞吐量
- 每任务成本 = 摊销 + 电费 + 通过率惩罚

**研究约束**：网络完全阻塞（subagent 环境），依赖内部知识（硬件规格是稳定事实：VRAM/带宽/TDP/MSRP）。

---

## 研究问题定义

**核心问题**：27B 模型在 64K 上下文、20 tok/s 最低吞吐约束下，哪种硬件配置每任务成本最低？

**候选硬件**（常见配置）：
1. RTX 3090×2（二手，24GB×2，760 GB/s，350W）
2. RTX 4090（24GB，1008 GB/s，450W）
3. RTX 5090（32GB，1792 GB/s，575W）
4. Mac Studio M3 Ultra（256GB，800 GB/s，约 200W 典型）
5. A6000×2（48GB×2，960 GB/s，300W×2）
6. RTX 6000 Ada×2（48GB×2，960 GB/s，300W×2）

**权重精度**：4bit / 8bit / 16bit（需权衡速度与通过率）

## 研究路径

### N1：KV cache 显存需求

**公式**：KV cache = 2 × 层数 × 隐藏维度 × 序列长度 × 字节数/元素

**27B 模型假设**（典型 LLaMA-3 架构）：
- 层数 = 60
- 隐藏维度 = 4096
- 注意力头 = 32
- 每头维度 = 128

**64K 上下文 KV cache**：
- BF16：2 × 60 × 32 × 128 × 64K × 2 bytes = 17.37 GB/流
- FP16：同上 = 17.37 GB/流
- FP8：17.37 / 2 = 8.68 GB/流

**关键洞察**：单卡 24GB 在 64K BF16/FP16 下放不下（17.37 GB/流 + 模型权重 54GB = 71GB >> 24GB）。

### N2：模型权重显存需求

**27B 模型权重**：
- FP16：27B × 2 bytes = 54GB
- 8bit：27B × 1 byte = 27GB
- 4bit：27B × 0.5 bytes = 13.5GB

**单卡 24GB 约束**：
- FP16：54GB >> 24GB → 放不下
- 8bit：27GB > 24GB → 放不下（需量化+KV 压缩）
- 4bit：13.5GB + KV cache 8.68GB（FP8）= 22.18GB < 24GB → 勉强放下（无余量）

**双卡 48GB 约束**：
- FP16：54GB > 48GB → 放不下
- 8bit：27GB + KV cache 17.37GB（BF16）= 44.37GB < 48GB → 放下
- 4bit：13.5GB + KV cache 17.37GB（BF16）= 30.87GB < 48GB → 放下（有余量）

### N3：吞吐量计算

**decode 瓶颈**：纯内存带宽（每 token 需读取全部权重 + KV cache）

**公式**：tokens/s = 内存带宽 / (模型权重显存 + KV cache 显存)

**3090×2 4bit**：
- 权重 13.5GB + KV 17.37GB = 30.87GB
- 带宽 760 GB/s（2 卡）
- tokens/s = 760 / 30.87 ≈ 24.6 tok/s > 20 tok/s → 满足

**3090×2 8bit**：
- 权重 27GB + KV 17.37GB = 44.37GB
- tokens/s = 760 / 44.37 ≈ 17.1 tok/s < 20 tok/s → 不满足

**4090 4bit**：
- 权重 13.5GB + KV 8.68GB（FP8，单卡 24GB 约束）= 22.18GB
- 带宽 1008 GB/s
- tokens/s = 1008 / 22.18 ≈ 45.4 tok/s > 20 tok/s → 满足

**5090 4bit**：
- 权重 13.5GB + KV 8.68GB（FP8，单卡 32GB 约束）= 22.18GB
- 带宽 1792 GB/s
- tokens/s = 1792 / 22.18 ≈ 80.8 tok/s > 20 tok/s → 满足

**M3 Ultra 4bit**：
- 权重 13.5GB + KV 17.37GB（BF16，统一内存 256GB）= 30.87GB
- 带宽 800 GB/s
- tokens/s = 800 / 30.87 ≈ 25.9 tok/s > 20 tok/s → 满足

**A6000×2 8bit**：
- 权重 27GB + KV 17.37GB（BF16，双卡 48GB×2=96GB）= 44.37GB
- 带宽 960 GB/s
- tokens/s = 960 / 44.37 ≈ 21.6 tok/s > 20 tok/s → 满足

**6000 Ada×2 8bit**：
- 权重 27GB + KV 17.37GB（BF16，双卡 48GB×2=96GB）= 44.37GB
- 带宽 960 GB/s
- tokens/s = 960 / 44.37 ≈ 21.6 tok/s > 20 tok/s → 满足

## 矛盾与张力

### CON-1：价格 vs 带宽
- **MECHANISM**：5090 带宽最高（1792 GB/s），但价格也最高（$2000 vs 3090 二手 $700）。在刚好过 20 tok/s 线的场景（3090×2 4bit），5090 的带宽优势不转化为成本优势。
- **VERIFICATION**：3090×2 4bit $0.017/任务 vs 5090 4bit $0.007/任务 → 5090 确实更便宜，但需 $2000 初始投资 vs $1400。
- **IMPACT**：长期（>2 年）5090 更优；短期（<1 年）3090×2 更优。

### CON-2：单卡 24GB 硬矛盾
- **MECHANISM**：单卡 24GB 在 64K BF16 KV 下放不下（17.37GB/流 + 权重 54GB = 71GB）。4bit 勉强放下（22.18GB），但无余量（多并发/长上下文直接 OOM）。
- **VERIFICATION**：4090 4bit 22.18GB < 24GB（余量 1.82GB）；5090 4bit 22.18GB < 32GB（余量 9.82GB）。
- **IMPACT**：单卡 24GB 不适合 64K 上下文；最小配置 = 双卡 48GB 或单卡 32GB（5090）。

### CON-3：4bit 速度 vs 通过率
- **MECHANISM**：4bit 量化速度快（3090×2 24.6 tok/s），但通过率低（0.7 vs 8bit 0.9）。通过率惩罚后成本反转。
- **VERIFICATION**：3090×2 4bit $0.017/任务 vs 3090×2 8bit（不满足 20 tok/s）→ 需 4bit。
- **IMPACT**：4bit 是 20 tok/s 约束下的唯一选择；通过率需实测校准。

### CON-4：M3 Ultra 统一内存 vs 带宽
- **MECHANISM**：M3 Ultra 统一内存 256GB（无显存限制），但带宽 800 GB/s（vs 5090 1792 GB/s）。大模型友好，但吞吐量受限。
- **VERIFICATION**：M3 Ultra 4bit 25.9 tok/s > 20 tok/s（满足），但 $2175/年（vs 5090 $1504/年）。
- **IMPACT**：M3 Ultra 适合大模型（>100B），27B 场景 5090 更优。
