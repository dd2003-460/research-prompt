# run1 — 开源最强模型风格自由研究（Llama-4-Maverick / Qwen3-235B 风格）

> 说明：本 run 无 R0 契约约束，自由发挥。问题：27B 模型本地部署，64K 上下文，缓存命中比 90:9:1，每并发流解码 ≥20 tok/s，求每任务成本最低的硬件。

## 0. 研究问题定义

**问题**：本地跑 27B 模型做固定任务（64K 上下文，prefix:input:output = 90:9:1，硬约束 decode ≥20 tok/s/并发流，通过率 <100%），哪种硬件每验收任务成本最低？

**范围**：含消费级/专业级 GPU、Apple Silicon 统一内存方案；不含云 API、不含 >27B 模型方案。
**输出量**：$/验收任务（美元 / 验收任务数）。
**通过标准**：给出可复算的成本公式 + 硬件排序。

## 1. 研究路径（自由展开）

### 1.1 先算"每任务要搬多少字节"

任务画像：64K 上下文，90% 前缀命中缓存 → 缓存 token 61440，新输入 5760，输出 640。

**关键洞察（第一感觉）**：前缀缓存命中意味着那 61K token 的 prefill 只做一次（会话建立时），之后每个任务只 prefill 新输入 5760 token。decode 阶段每生成 1 个 token 都要读一次完整 KV cache。

**KV cache 大小估算**（27B，典型 Llama 风格架构）：
- 假设 64 层、GQA 8 个 KV 头、每头 128 维 → KV/token = 64 × 2 × 8 × 128 × 2 bytes(FP16) = 256 KB/token
- 64K 上下文 → KV ≈ 64000 × 256KB = **16 GB**（FP16）；FP8 → 8 GB

decode 每 token 读的数据量 ≈ 模型权重 + KV cache 读取（注意力）。
- 4bit 权重 ≈ 13.5 GB；8bit ≈ 27 GB
- 每生成 1 token：读权重 13.5GB（4bit）+ KV 随机读 ≈ 0.5–1 GB
- **4bit 下每 token ≈ 15 GB 内存读取 → 带宽决定 tok/s**

### 1.2 硬件候选与带宽

| 硬件 | 显存 | 带宽 | 4bit 27B 理论 decode | 价格(二手/新) |
|------|------|------|------|------|
| RTX 3090×2 (NVLink) | 48GB | 936 GB/s ×2 | ~60 tok/s 每卡 | $800×2 |
| RTX 4090 | 24GB | 1008 GB/s | 4bit 勉强放下，~65 tok/s | $1600–2000 |
| RTX 5090 | 32GB | 1792 GB/s | ~100+ tok/s | $2400+ |
| Mac Studio M3 Ultra | 256GB | 819 GB/s | ~55 tok/s | $4000–9000 |
| A6000×2 | 96GB | 768×2 GB/s | ~50 tok/s | $6000+ |
| RTX 6000 Ada×2 | 96GB | 960×2 | ~60 tok/s | $12000+ |

**关键判断**：decode 是纯带宽瓶颈。20 tok/s 硬约束在 4bit 下要求有效带宽 ≥ 20 × 15GB = 300 GB/s（单卡即可满足，3090/4090/M3 Ultra 全过）。所以 20 tok/s 不是强约束，**真正的约束是 KV cache + 权重能否放进显存、并发流数**。

### 1.3 每任务成本建模

```
每任务成本 = (硬件一次性成本 / 寿命任务数) + 电费(任务时间 × 功耗 × 电价)
任务时间 = prefill(新输入5760 tok) + decode(输出640 tok) / 速度
```

假设：寿命任务数 10 万（3 年），电价 $0.1/kWh，8bit 通过率 90%（重做 1.11 次），4bit 通过率 75%（重做 1.33 次）。

**prefill 速度**：新输入 5760 token 是 compute-bound（prefill FLOPs ≈ 2×27B×5760 ≈ 311 TFLOP），4090 约 80 TFLOPS 有效 → ~4s；3090 约 35 → ~9s；M3 Ultra 约 25 TFLOPS → ~12s。decode 640 tok @ 50 tok/s → 12.8s。单任务墙钟 ≈ 15–22s。

**电费/任务** ≈ 350W × 18s/3600 × $0.1 ≈ **$0.00175**（可忽略）。
**摊销/任务** = 卡价 / 10 万：
- 3090×2: $1600/100000 = $0.016
- 4090: $1800/100000 = $0.018
- 5090: $2500/100000 = $0.025
- M3 Ultra 256GB: $9000/100000 = $0.09

**通过率惩罚**（重做）：
- 3090×2 (8bit): $0.01775 / 0.9 ≈ $0.0197
- 3090×2 (4bit): $0.01775 / 0.75 ≈ $0.0237
- M3 Ultra (8bit): $0.0918 / 0.9 ≈ $0.102

### 1.4 排序（初步）

1. **3090×2 (48GB)**：$0.020/验收任务 — 最便宜，带宽足够
2. **4090**：$0.020 — 略贵但单卡省心，prefill 更快
3. **5090**：$0.025–0.028 — 贵但快
4. **M3 Ultra 256GB**：$0.10+ — 显存巨大但带宽贵（$/GB 最贵）

## 2. 矛盾与张力

1. **价格 vs 带宽**：3090 最便宜但二手风险高；5090 快但溢价 60%。→ 影响 ±20% 成本排序。
2. **4bit 速度 vs 通过率**：4bit 快 30% 但通过率可能掉 15pp → 重做成本吃掉速度收益。→ 未解，需实测 ≥100 任务。
3. **单卡 4090 vs 双卡 3090**：4090 24GB 放 4bit+64K KV 刚好（13.5+16=29.5GB > 24GB ❌），必须 FP8 KV 或缩上下文；3090×2 48GB 从容。→ **4090 单卡在 64K FP16 KV 下放不下，这是硬矛盾**。
4. **并发数**：题目说"每个并发流 ≥20 tok/s"，若需要 N 并发，显存要 ×N 的 KV → 直接推向大显存方案（M3 Ultra 256GB 或 3090×4）。题目未给 N，**N=1 假设是最大不确定性**。

## 3. 计算与验证（关键计算链）

- KV cache = 64 层 × 2 × 8 KV头 × 128 dim × 2B × 64K token = 16 GB [F，假设架构参数，需按实际模型核对]
- 4bit 每 decode token 读 ≈ 13.5GB + KV ≈ 15GB → 20 tok/s 需 300 GB/s [F]
- 3090×2 decode ≈ 936×2/15 ≈ 125 tok/s（理论上限，实际 50–60）[E, ±30%]
- 每任务 $ = $1600/1e5 + 0.00175 = $0.01775 [F]；8bit 通过率 0.9 → $0.0197 [F+E]

## 4. 结论与置信度

**瓶颈**：显存容量（权重+KV）决定可行域，带宽决定速度；20 tok/s 约束不 bind。
**推荐**：3090×2（二手 $800/张，8bit 运行）— 每验收任务 ≈ $0.02，比 4090 便宜，比 M3 Ultra 便宜 5×。
**主要矛盾**：4bit 通过率未实测；并发数 N 未知。
**置信度**：0.6 — 架构参数（层数/头数）假设未经实际模型确认，N 并发未知，4bit 通过率纯估计。

- **瓶颈**：显存容量 > 带宽 > 20tok/s 约束（后者不 bind）
- **矛盾**：4090 单卡 24GB 放不下 4bit+64K KV；4bit 通过率 vs 速度收益未解；并发数 N 未定义
- **置信度**：0.6（架构假设 + N 未知 + 通过率估计）
