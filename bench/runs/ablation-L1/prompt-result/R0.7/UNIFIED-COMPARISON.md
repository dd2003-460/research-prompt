# R0.3 vs R0.7 统一判官协议对比 (2026-11-06 修正)

## 问题

之前报告的分数来自**不同判官调用协议**：
- R0.3 orig run1-3: 用完整文本 + 更宽松 judge prompt → 18/18/18
- R0.7 run1-3: 用不同 truncation → 10/18/18
- n9 补跑: 用 temp=0 + 15k truncation + 严格 JSON-only → 16/11/16/16

这导致跨变体比较无效。

## 修正方法

对**所有 runs** 用完全相同的判官协议重评：
- model: qwen3.8-27b, temperature=0.0
- input: 前 15,000 chars（truncation）
- system: 固定 10 维 rubric + JSON-only 输出
- max_tokens: 500

## 结论

1. **R0.7 确实比 R0.3 差**（Δ mean = -2.67），即使控制了判官协议。
2. **C4 归零是真实的**：R0.3 在 7 个成功 run 中 C4 最低=1，从未归零；R0.7 run1 C4=0。
3. **但 R0.3 也不是"完美 18 分"**：统一协议下最高只有 16，mean 14。之前的 18 是宽松判官的产物。
4. **Stall 模式不同**：R0.3 有 22% 硬停（不出五节），R0.7 没有 stall 但成功 run 内部质量波动更大（σ 4.51 vs 2.24）。
5. **实操结论不变**：R0.3 定版。+107B C2 强化确实引入退化（主要是 C4 注意力竞争 + 整体质量方差增大）。

## 对 SUMMARY 的影响

SUMMARY.md 中所有引用 "18/20" 的地方需要加注"宽松判官协议"或更新为统一协议分数。
核心结论（R0.3 最优、prompt 层无改进空间）不受影响，只是绝对分数下移。
