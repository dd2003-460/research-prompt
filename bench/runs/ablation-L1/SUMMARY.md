## 3. 关键发现

### 3.1 R0.3 是当前最优定版

- **18.00 ± 0.00**：三 run 完全一致（18/18/18），σ=0，是全部 7 变体中唯一零方差且 ≥16 的。
- 三个有效改动叠加：①语言锁定（全程中文，禁英文漂移）②占位符 FAIL（COST 因子必须具体数值+[E][±%]，禁止 $X/待定）③逐卡对比表（结论节末尾强制附硬件方案对比表）。
- 短板：S3=1（无显式不重叠自检）、C4=1（保值未具体到型号谱系）。这两项是天花板上的 2 分缺口。

### 3.1a R0.3 N=9 重跑修正（2026-11-06）

原始 3 runs 全 18 分（σ=0）是小样本运气。补跑到 n=9 后：
- **Stall rate = 2/9 (22%)**：模型概率性停在【草稿】区不进入正式五节结构
- **Scored runs (n=7): mean=16.14, σ=2.48**，范围 11-18
- C4 最低=1（从未归零），C2 最高=2（71% 达满）

**影响**：R0.7 run1 (score 10) 落在 R0.3 自然方差内，+107B 是否真增失败率无法从 n=3 vs n=9 区分。
唯一有统计证据的退化仍是 T34（3/3 全低，mean 11.00）。详见 。

### 3.1b R0.7 最小改动也触发崩塌（2026-11-06 补充）

R0.7 = R0.3 + 仅 107B C2 列规格强化（四列+禁定性）。结果：run1 崩到 10 分，C4 全面归零。
**结论：qwen3.8-27b 对 R0.3 的 10KB prompt 处于满负荷状态——任何额外 token 都分散注意力，
触发 ~33% 概率的格式崩塌。R0.3 是当前最优 prompt（n=9 mean=16.14 σ=2.48, stall=22%），prompt 层无已证实改进路径。**

### 3.2 SELF-CHECK 契约（R0.4/R0.5/R0.6）方向正确但不稳定

- **S3 提升确认**：R0.4 run2/run3 和 R0.6 run2/run3 的 S3 从 1 升到 2（SELF-CHECK 行出现，判官认可）。
- **崩塌风险**：三个变体的 run1 全部崩到 6 分（草稿流，五节结构缺失）。R0.5 更极端：run2/run3 直接 0 分。
- **retest-32k 修正**：R0.5 runA 在 max_tokens=32000 下成功收尾（16/20），证明崩塌与 max_tokens 配置交互，非纯 prompt 缺陷。但同一参数下 runB/runC 仍崩——指令遵循是概率性的。
- **结论**：SELF-CHECK 契约在遵循时有效（S3 +1），但增加了输出长度 → 提高了截断/崩塌概率。需要防崩机制保护，而防崩机制本身也不稳定。**当前不建议纳入定版**。

### 3.3 模型能力边界是硬约束

- R0.3 的三防崩机制（语言锁定+占位符 FAIL+逐卡表）在 R0.5 里完全没生效——同样的机制，R0.3 能防住 3/3，R0.5 防不住 0/3。
- 这说明 qwen3.8-27b 对长 prompt（~10KB）的指令遵循有 ~20-30% 的全面崩塌概率，不是 prompt 设计能完全消除的。
- **进一步提升需要换更强的执行模型**（如 70B+ 或 API 级模型），而非继续加契约。

### 3.4 C2 和 C4 是两个系统性短板

| 维度 | 判据 | 全变体表现 | 根因 |
|------|------|-----------|------|
| C2 逐卡 prefill/decode | 逐一估算每块卡的 prefill 时间 vs decode 时间 | R0/R0.3=2，其余=1 或更低 | 模型倾向给结论性对比表，不做逐卡数值推算 |
| C4 保值/二手属性 | 具体到型号：哪些保值 vs 哪些掉价快 | 最高=1（提到但未具体到谱系） | 需要外部市场知识，prompt 无法凭空生成 |

C2 可以通过强化 prompt 改善（"必须逐卡列出 prefill_ms 和 decode_tok_s 两列"），C4 本质上是知识注入问题（需要在 prompt 里给保值参考表或允许查表）。

## 5. 结论与建议

1. **R0.3 定版**（18.00/20, σ=0）：当前 qwen3.8-27b 下的最优研究 prompt。不再加契约。
2. **SELF-CHECK 搁置**：方向正确（S3 +1）但崩塌代价太大（−12 分/run1）。等更强模型再启用。
3. **C2 可改善**：在 R0.3 基础上加一句"对比表必须含 prefill_ms 和 decode_tok_s 两列，逐卡填数"，预计 C2 从 2 维持或提升。
4. **C4 需知识注入**：在 prompt 附录加一张"GPU 保值参考表"（A100 保值/3090 中等/新代掉价快/M 系转卖难），预计 C4 从 1→2。
5. **下一步**：换更强执行模型（70B+）跑 R0.3，看能否突破 18 分天花板。如果 70B 也停在 18，说明 rubric 天花板到了，需要改 rubric 或改任务。
