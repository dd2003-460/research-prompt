# research-prompt — 研究 Prompt 基准

**总目标**：产出一份「研究 prompt」——naive subagent 只拿 prompt+一句话任务+缺失信息清单，就能稳定执行「调研→推理→计算」循环，产出可验证的研究结论。

**定位**：
- decomp = 分解 prompt（把复杂问题拆成可计算的树）
- research-prompt = 研究 prompt（拿到分解树后，根据缺失信息调研，根据矛盾信息推理和计算）

**研究 Prompt 核心能力**：
1. **缺失信息识别**：从分解树中识别哪些节点是「黑盒」（查不到/量不出），生成调研问题清单
2. **矛盾挖掘**：从分解树中识别哪些节点之间存在张力/冲突，生成验证问题清单
3. **推理与计算**：根据调研结果，用公式/模拟/实测推算关键指标
4. **产投比评估**：计算每个候选方案的投入（卡钱+电费+时间）vs 产出（验收任务数），输出性价比排序
5. **风险与方差**：估算成本的不确定性（价格波动/通过率方差/效率衰减），输出置信区间
6. **变化趋势**：分析硬件价格/性能/效率的时间趋势，预测未来 1-2 年的最优方案

**Benchmark 任务**：27B 本地推理硬件选型（与 decomp 同任务，但 research-prompt 需要在分解树基础上做研究）

**候选方案**（研究 prompt 需要自己调研，不直接给）：
- GPU：3090×2/×4、A100×1/×2、L40S×1、V100×8
- Apple：M2 Ultra 192GB
- 精度：4bit/8bit/16bit
- 部署：llama.cpp/vLLM

**任务画像**（与 decomp 相同）：
- 27B 模型，固定任务
- 90:9:1 缓存命中比
- 64K 上下文
- 20 tok/s 硬约束
- 通过率非 100%（需重做）

**评估维度**（20 分制 rubric）：
- 结构（10 分）：调研问题清单完整性 / 矛盾清单完整性 / 计算链完整性 / 产投比排序 / 风险评估
- 内容（10 分）：调研数据准确性 / 推理逻辑正确性 / 计算结果准确性 / 产投比合理性 / 趋势预测合理性

**计划**：
- P0：建档（✅ 2026-10-23）
- P1：研究 prompt 原型（白话版：文件夹式分层+完整/不重叠两检+黑盒+矛盾+调研+推理+计算）
- P2：研究 prompt × 3 run 实跑（27B 硬件选型任务）
- P3：20 分制 rubric 评分
- P4：对标 decomp（C0/C9-plain）+ 开源最强模型
- P5：汇总对标表（research-prompt vs decomp vs 开源）

**与 decomp 的关系**：
- decomp = 阶段 1（分解）
- research-prompt = 阶段 2（研究）
- 完整流程：decomp（分解树）→ research-prompt（调研+推理+计算）→ 最终报告

**关键洞察**（用户 m00885）：
- p/d 比例瓶颈 / cache 加速和极限 / 混合负载效率远低于峰值 = 研究过程中发现的矛盾
- TCO 完整构成 / 成本风险 / 方差 / 产投比 / 变化趋势 = 研究 prompt 需要量化的维度
- 这些不是分解 prompt 能解决的，需要研究 prompt（调研+推理+计算）
